# 请求参数推导规则

## 三界推导法则

FastAPI 根据参数名是否在路径中、类型标注以及是否有默认值，自动将请求数据解析为 Path、Query 或 Body：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class ItemCreate(BaseModel):
    title: str

@app.get("/items/{item_id}")
def get_item(
    item_id: int,    # 1. Path 路径参数：名字在 URL 模板 {item_id} 中出现
    skip: int = 0,   # 2. Query 查询参数：标量类型，不在路径中，有默认值（选填）
    token: str,      # 3. Query 查询参数：标量类型，不在路径中，无默认值（必填！漏传报 422）
):
    return {"item_id": item_id, "skip": skip, "token": token}

@app.post("/items/")
def create_item(payload: ItemCreate):  # 4. Body 请求体：继承自 BaseModel 的复合对象
    return payload
```

## 422 错误精准定位（loc）

数据类型不符或漏传必填参数时，FastAPI 统一返回 HTTP 422，响应体中的 `loc` 数组直接指出错位层级：
- 路径参数错：`loc: ["path", "item_id"]`
- 查询参数错：`loc: ["query", "token"]`
- 请求体字段错：`loc: ["body", "title"]`

## 常见避坑

- **路径占位符拼错**：若路由写 `@app.get("/items/{item.id}")` 而形参写 `item_id`，因名称未精确匹配，FastAPI 会把 `item_id` 降级为 Query 参数（`?item_id=...`），导致路径匹配报 404。
- **测试 422 拦截**：Swagger UI 会在浏览器前端拦截不合法的必填表单；测试 422 边界应使用 curl、Postman 或自动化测试直接发包。
