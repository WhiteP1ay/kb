# 类型收窄与守卫

## 类型谓词（param is Type）

告诉 TypeScript 编译器：当且仅当当前守卫函数返回 `true` 时，传入的参数被确切收窄为目标类型。

```typescript
// 类型谓词语法：val is string
function isString(val: unknown): val is string {
  return typeof val === "string";
}

function processValue(x: unknown) {
  if (isString(x)) {
    // 成功收窄为 string，直接拥有字符串专属方法提示
    console.log(x.toUpperCase());
  }
}
```

- **替代危险的 `as` 断言**：使用类型谓词是收窄 `unknown` 类型的最佳实践，比强制类型断言（`as string`）更安全。
- **信任机制与避坑**：编译器**不会校验函数体内的检查逻辑是否真的一致**。如果函数内部写了 `typeof val === "number"` 却声明为 `val is string`，TS 依然会盲目信任！类型谓词是开发者对编译器的契约承诺，务必确保运行时逻辑正确。

## never 类型：不可能到达的终点

`never` 表示永远不可能出现的值（空集）。

### 1. 穷举检查（Exhaustive Check）
防止在 `switch` 或 `if-else` 分支中遗漏新增枚举类型，编译期强制排查：

```typescript
type Action = { type: "login" } | { type: "logout" } | { type: "register" };

function handleAction(act: Action) {
  switch (act.type) {
    case "login": return "登录";
    case "logout": return "登出";
    case "register": return "注册";
    default: {
      // 若 Action 新增了成员而此处未处理，赋值给 never 会直接引发编译报错！
      const _exhaustiveCheck: never = act;
      throw new Error(`Unhandled action: ${_exhaustiveCheck}`);
    }
  }
}
```

### 2. 永远无法返回的函数
抛出异常或死循环的函数返回值类型为 `never`：
```typescript
function throwError(msg: string): never {
  throw new Error(msg);
}
```

- **void vs never**：`void` 表示函数正常跑完但没有返回值（隐式返回 `undefined`）；`never` 表示该函数执行路径**永远走不到正常终点**。
