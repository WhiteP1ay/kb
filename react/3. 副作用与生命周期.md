# 副作用与生命周期

## useEffectEvent：抽离非响应式副作用逻辑

让 `useEffect` 能够读取最新的 props/state，却**不需要把它们声明在依赖数组里**，彻底终结“为了读最新值导致 effect 疯狂重复触发”的死循环。

```jsx
// 实验性 API：function ChatRoom({ roomId, theme })
function ChatRoom({ roomId, theme }) {
  // 用 useEffectEvent 包裹非响应式逻辑
  const onConnected = useEffectEvent(() => {
    showNotification("Connected!", theme); // 读到了最新 theme
  });

  useEffect(() => {
    const connection = createConnection(roomId);
    connection.on("connected", () => {
      onConnected(); // 触发事件
    });
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]); // 依赖数组只有 roomId！theme 改变绝不会导致断线重连！
}
```

- **核心心智**：
  - 响应式依赖（决定 effect 什么时候重新开工，如 `roomId`）放在 `useEffect` 依赖项中。
  - 非响应式逻辑（只是执行时顺便读取最新值，如 `theme`、打点参数）用 `useEffectEvent` 抽离，不入依赖数组。

## Activity 组件（React 19.2 keep-alive）

声明式控制屏幕不可见区域的驻留行为，完全等价于 Vue 的 `<KeepAlive>`。

```jsx
import { Activity } from "react";

function TabContainer({ activeTab }) {
  return (
    <>
      <Activity mode={activeTab === "home" ? "visible" : "hidden"}>
        <HomeTab />
      </Activity>
      <Activity mode={activeTab === "profile" ? "visible" : "hidden"}>
        <ProfileTab />
      </Activity>
    </>
  );
}
```

- **对比条件渲染（`{show && <Comp />}`）**：条件渲染隐藏时组件彻底卸载，切回来时滚动位置、输入框草稿全部丢失，生命周期重跑；`Activity` 完整保留内部 state 与 DOM 状态。
- **对比 CSS `display: none`**：CSS 隐藏时组件的定时器、长轮询、effect 依然在后台狂跑耗电；`Activity` 处于 `hidden` 模式时会**自动清理并挂起内部 effect**，更省资源，且在浏览器空闲时以低优先级静默更新。
