# 渲染优化与并发调度

## React.memo：浅比较跳过渲染

高阶组件，默认对前后 props 进行 `Object.is` 浅比较。若所有 props 引用均未变，则直接复用上次渲染结果。

```jsx
const UserCard = React.memo(function UserCard({ user, onSelect }) {
  return <div onClick={() => onSelect(user.id)}>{user.name}</div>;
});

// 自定义比较函数（按需）：返回 true 表示相等（跳过渲染）
const FastCard = React.memo(UserCard, (prev, next) => prev.user.id === next.user.id);
```

- **滥用即负优化**：`memo` 本身每次都有遍历对比所有 props 的 CPU 开销。对于子树小、props 频繁变化的组件，加了反而变慢。
- **必须配合稳定引用**：如果父组件传下去的 `onClick` 是内联箭头函数，或者对象是临时构造的，浅比较每次必定失败，`memo` 直接形同虚设。必须搭配 `useCallback` / `useMemo`。
- **使用基准**：只在“子树庞大渲染代价高”且“props 变化频率低”的纯展示组件上使用。

## useDeferredValue：可中断的优先级调度

将某个非紧急状态的更新推迟，优先保障紧急更新（如用户键盘输入、点击高频响应），防止大数据重绘阻塞界面造成掉帧卡死。

```jsx
function SearchPage() {
  const [query, setQuery] = useState("");
  // deferredQuery 滞后于 query 更新
  const deferredQuery = useDeferredValue(query);

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      {/* 当新输入到来时，旧的滞后渲染会被 React 立即中断丢弃，优先响应输入 */}
      <SlowList search={deferredQuery} />
    </>
  );
}
```

- **与防抖（Debounce）的本质差异**：
  - `debounce`：必须傻等 N 毫秒（哪怕机器性能过剩也得干等），属于**固定时间延迟**。
  - `useDeferredValue`：无等待时间。硬件好算得快就立刻出，算得慢就等空闲出；输入一进来立刻把正在算的半成品打断，属于**优先级驱动的抢占式调度**。
