# 状态传递与外部同步

## Context API：跨层传值而非状态管理

Context 的本质是**跨层传值隧道**，绝非完整状态管理系统。适合传递更新频率低、天然全局的数据（主题、语言、登录用户）。

```jsx
// 最佳实践：按职责拆分 Context，避免大杂烩
const UserContext = createContext(null);
const ThemeContext = createContext("light");

function App() {
  const [theme, setTheme] = useState("dark");
  // 必须用 useMemo 稳定 value 引用，避免父组件无关重渲染导致 Context 消费者全灭
  const themeValue = useMemo(() => ({ theme, setTheme }), [theme]);
  return (
    <ThemeContext.Provider value={themeValue}>
      <Page />
    </ThemeContext.Provider>
  );
}
```

- **重渲染铁律**：Context 内部任何字段变化，**所有消费该 Context 的子组件全部无条件重渲染**（这是设计取向，非 Bug）。
- **选型分工**：Context 负责“值怎么跨层传下去”；Zustand/Redux 等状态库负责“精确订阅：谁该更新、谁不该更新”。

## useSyncExternalStore：并发渲染防撕裂

React 18 并发渲染（Concurrent Mode）可能让一次渲染被中断分片执行。如果在此期间外部 store 发生变化，不同组件在同一轮渲染中会读到不同版本的数据，导致 UI 状态不一致（**状态撕裂 Tear**）。

`useSyncExternalStore` 强制 React 在渲染阶段以**同步快照**的方式读取外部数据源：

```jsx
import { useSyncExternalStore } from "react";

// 三个参数：订阅函数、客户端读快照、服务端读快照
function useOnlineStatus() {
  return useSyncExternalStore(
    (callback) => {
      window.addEventListener("online", callback);
      window.addEventListener("offline", callback);
      return () => {
        window.removeEventListener("online", callback);
        window.removeEventListener("offline", callback);
      };
    },
    () => navigator.onLine,
    () => true // SSR 保底快照
  );
}
```

- **机制与代价**：渲染期间若发现快照过期，React 会丢弃本轮渲染重新开始整轮渲染。以多一次渲染为代价，彻底消除并发撕裂。
- **定位**：应用层业务代码极少直接手写，它是 Zustand、Redux、TanStack Query 等库底层对接 React 18+ 的压舱石。
