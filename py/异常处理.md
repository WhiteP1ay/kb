# 异常处理：try/except/else/finally

## 是什么

Python 的异常处理，术语是 try/except，不是 JS 的 try..catch。except 按错误类型接住，接不住就向上抛。

## 怎么用

唯一模板：

```python
try:
    result = func(*args, **kwargs)    # 可能出错的代码
except ConnectionError as e:          # 按类型接；as e 拿异常对象（≈ JS catch(e)）
    print("连不上:", e)
except Exception:                     # 兜底接所有
    ...
finally:                             # 无论如何都执行：资源清理
    ...
```

重试模式（成功提前返回，最后一次失败重新抛出）：

```python
for i in range(max_times):
    try:
        return func(*args, **kwargs)   # 成功：直接返回，循环都不用走完
    except ConnectionError:
        if i == max_times - 1:
            raise                      # 裸 raise：原样抛当前异常
```

## 关键点

- 裸 `raise`（不加类型）= 重新抛出当前异常，保留原始消息和 traceback 起点；`raise XxxError` = 新建异常，会丢原始信息
- 自定义异常继承 Exception：`class TokenExpired(Exception): pass`
- except 块里 if 不满足可以什么都不写，自然往下走，不需要 pass/continue
- try 成功且没有提前 return/break 时 else 才执行；try 里 return 后 else 永远不执行

## 陷阱

- except 里写 `raise ConnectionError` 丢原始消息和来源，调试时对着空异常发懵——用裸 raise
- `else: continue` 挂在 try 上多半是误解：else 是「try 没抛异常时」的补充分支，不是循环的 else
- 术语混用：try..catch 是 JS 的，Python 叫 try/except，as e 才相当于 catch(e)
