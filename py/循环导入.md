# 循环导入

## 是什么

A 导入 B、B 又导入 A。Python 的 import 是顺序执行的，A 加载到一半时 B 回头要 A 还没定义的名字，直接 `ImportError`。ESM 有 hoisting 多半能跑，Python 顺序执行更严格，必须主动破环。

## 怎么用（三种解法）

```python
# 1. 延迟导入：函数内 import，用到才导入（治标）
class A:
    def __init__(self) -> None:
        from b import B
        self.b = B()

# 2. 重构：把公共部分抽到第三个模块 c，a 和 b 都不再互相 import（治本）
# 3. 类型标注专用：from __future__ import annotations + TYPE_CHECKING 块，
#    运行时根本不导入，只给检查器看
```

## 关键点

- 报错链读法：`a.py → b.py → a.py`，顺着栈看谁先卡住
- 延迟导入安全靠 sys.modules 缓存：函数被调用时对方模块早已加载完，import 只是取缓存
- 破环即可，哪边延迟都行——关键是让「互相 import」不再发生在模块加载期

## 陷阱

- 报错 `cannot import name 'B' from 'b'` 或 `partially initialized module`，本质都是「对方还没定义完」
- `consider renaming` 之类的提示是干扰项，别理
- 入口脚本以 `__main__` 身份进 sys.modules，报错格式略有差异，机制不变
