## 包和模块

模块（module）就是一个独立的 `.py` 文件。
包（package）包含一个 `__init__.py` 文件的**目录**。

不能直接执行有相对路径的模块。
因为会当做脚本执行，Python 会把当前直接运行的脚本命名为 `__name__ = "__main__"`，也找不到父级包。
可以在包根目录下使用-m，模块模式执行。
```python
python -m shop.pricing
```

## 包初始脚本

\_\_init\_\_.py：执行入口，只要有人 `import` 这个包，Python 就会**最先执行**该文件里的代码。

通常写：
```python
from .cart import Cart

from .pricing import apply_discount
```

## 包导入

`import` 是**普通语句，不是声明**。执行到那一行才生效，放函数里、if 里都行。

```python
def f():
    from b import B   # 延迟导入：用到时才导入，b 早已加载完，拿缓存
    return B()
```
- 把 import 移到具体函数内是解决循环引用的方法之一
- 第一次 import 会**执行被导入文件的全部代码**（副作用），然后结果缓存在 `sys.modules` 字典里，模块一生只加载一次。
- 第二次 import 不再执行文件，直接从 `sys.modules` 拿缓存

python找模块不像 js 可以`../../components/Button`多层级找。

通常是一个点 `.` 代表当前目录；多一个点，就往上一层。
即`from ..utils import helper`表示父级目录。 

跨层级不要写一堆点 `.` ，要绝对路径导入。
```python
from my_app.core.config import settings 
# 像极了前端的 '@/core/config'
```


## 包导出

模块顶层定义的任何变量、函数、类，甚至顶层 `import` 进来的外部包，默认全都可以被外部导入。

下划线\_开头的，被约定成私有。但只是约定，具名导入仍然会被解释器执行。只会约束通配导入。

\_\_all\_\_：包的对外接口清单，类型是 `list[str]`。作用是通配导入过滤。

```python
# shop/__init__.py
from .cart import Cart
from .pricing import apply_discount

__all__ = ["Cart", "apply_discount"]
```
