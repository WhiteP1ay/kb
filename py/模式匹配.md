# Python 模式匹配 match / case

## 是什么

`match / case` 用模式检查一个值的结构，并且可以在匹配时从中取出数据。

它不是 JavaScript `switch` 的简单换皮。`case` 后面写的是“模式”，模式既可以负责比较，也可以负责捕获数据。

```python
status = "open"

match status:
    case "open":
        print("已开启")
    case "closed":
        print("已关闭")
    case _:
        print("未知状态")
```

Python 从上到下检查各个 `case`，只执行第一个成功匹配的分支，没有 JavaScript `switch` 的贯穿执行。

## 字面量负责比较

字符串、数字、`True`、`False` 和 `None` 等字面量表示值匹配：

```python
match status:
    case "open":
        print("匹配字符串 open")
```

这里要求 `status` 的值确实是 `"open"`。

多个候选值可以使用 `|`：

```python
match status:
    case "open" | "pending":
        print("仍在处理中")
```

## 裸名字负责捕获

`case` 中的裸变量名不会读取它原来的值，而是匹配任意值，并把该值绑定给这个名字。

```python
target = "open"
status = "closed"

match status:
    case target:
        print(target)
```

输出：

```text
closed
```

`case target` 是捕获模式，可以近似理解为：

```python
target = status
```

因此可以把“捕获变量”暂时理解为“接值变量”。

## 通配符 `_`

`_` 匹配任意值，但不保存该值：

```python
match status:
    case "open":
        print("已开启")
    case _:
        print("其他情况")
```

通配符通常放在最后，承担兜底分支。

## 从结构中捕获数据

模式匹配的主要价值不是替代 `if / elif`，而是同时检查结构并取出数据。

```python
ticket = {
    "id": 42,
    "status": "closed",
}

match ticket:
    case {"id": ticket_id, "status": "open"}:
        print("已开启", ticket_id)
    case {"id": ticket_id, "status": actual_status}:
        print(ticket_id, actual_status)
```

第二个模式中：

- `"id"` 和 `"status"` 是要检查的字典键。
- `ticket_id` 捕获 `42`。
- `actual_status` 捕获 `"closed"`。

输出：

```text
42 closed
```

映射模式默认允许原字典含有模式中没有写出的其他键。

序列也可以按结构匹配和捕获：

```python
command = ["move", 10, 20]

match command:
    case ["move", x, y]:
        print(x, y)
```

其中 `"move"` 负责比较，`x` 和 `y` 分别捕获 `10` 和 `20`。

## guard：捕获后增加条件

如果需要与一个已有变量的值动态比较，不能直接把该变量裸写在 `case` 中，应使用 guard：

```python
expected = "open"
status = "closed"

match status:
    case value if value == expected:
        print("匹配")
    case _:
        print("不匹配")
```

执行逻辑是：

1. `case value` 先捕获当前值。
2. `if value == expected` 再检查附加条件。

枚举成员等带限定名的值也能用于值模式，例如 `case Status.OPEN:`；裸名字 `OPEN` 仍会被当成捕获变量。

## 捕获变量的作用域

`case` 不会创建独立作用域。成功匹配后，捕获的变量仍可在 `match` 外使用：

```python
status = "closed"

match status:
    case value:
        print("inside:", value)

print("outside:", value)
```

输出：

```text
inside: closed
outside: closed
```

不要在无法保证对应模式成功时，依赖某个捕获变量一定存在。

## 与 JavaScript switch 的关键区别

- JavaScript `case expression` 通常计算表达式并与目标值比较。
- Python `case pattern` 描述目标值应该具有的值或结构。
- Python 裸名字是捕获，不是读取同名变量。
- Python 只执行第一个成功匹配的分支，不需要 `break`。
- Python 可以直接解构字典、序列和对象，并保存其中的数据。

## 容易混淆的点

- `case "open"` 是值比较，`case target` 是捕获。
- 捕获模式几乎可以匹配任何值，通常应放在最后，否则后续分支可能永远无法到达。
- `_` 只匹配，不保存。
- 多个 `case` 不会依次全部执行。
- 与已有变量动态比较时使用 guard。
- 成功捕获的变量不会被限制在 `case` 分支内部。

## 闭卷自测

```python
expected = "open"
ticket = {"id": 42, "status": "closed"}

match ticket:
    case {"id": ticket_id, "status": "open"}:
        print("A", ticket_id)
    case {"id": ticket_id, "status": actual_status}:
        print("B", ticket_id, actual_status)
    case _:
        print("C")

print(expected)
```

1. 程序最终输出什么？
2. 哪些部分负责比较，哪些名字负责捕获？
3. 为什么不会同时执行 `A` 和 `B`？
4. 如果要判断捕获到的状态是否等于 `expected`，guard 应该怎样写？
