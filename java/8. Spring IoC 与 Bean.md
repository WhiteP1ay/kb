# Spring IoC 与 Bean

Spring 的立足之本就是 **IoC（控制反转）** 与 **DI（依赖注入）**。它把创建和组装对象的控制权从开发者手中收缴，由容器统一管理分配。

## 1. 前端类比：Vue `provide / inject`

- **传统代码（强耦合）**：类内部自己 `new SmsService()`。一旦 `SmsService` 改了构造参数或测试需要 mock，所有调用方代码全得跟着修改。
- **IoC 控制反转**：类只要声明需要什么，Spring 容器（像 Vue provide 一样）统一建好并在初始化时塞（inject）进来。

## 2. 怎么把类交给 Spring？

- **自己写的业务类**：在类头上贴标签，Spring 启动组件扫描（Component Scan）自动收编：
  - `@Component`：基础组件标签。
  - `@Service`、`@Repository`、`@RestController`：业务语义化马甲（底层全都是 `@Component`）。
- **第三方类（改不了源码）**：写配置工厂类，用 **`@Configuration` + `@Bean`** 包装：
  ```java
  @Configuration
  public class AppConfig {
      @Bean // 方法返回的实例被收录进容器成为 Bean
      public RestTemplate restTemplate() {
          return new RestTemplate();
      }
  }
  ```

## 3. 依赖注入：首选构造器注入

```java
@Service
public class OrderService {
    private final SmsService smsService; // 声明为 final，不可变防篡改

    // 官方最推荐：构造器注入。防空指针，单测可脱离 Spring 直接 new 传参
    public OrderService(SmsService smsService) {
        this.smsService = smsService;
    }
}
```

## 4. 生产铁律：单例 Bean 必须是「无状态」的！

Spring 中的 Bean **默认全部是单例（Singleton）**，全国所有用户的 HTTP 并发请求都在共享访问同一个对象！
- **严禁在 `@Service` 里定义有状态的成员变量**（如 `private Long userId;`）！
- **为什么？** 堆内存是全线程共享的。张三的线程刚把 `userId` 改成 101，李四的线程一进来就会把它覆盖成 102，发生严重的串号并发事故！
- **数据存哪？** 必须全部放在**方法入参**和**局部变量**里！因为方法内的变量存放在每个线程各自的「独立栈内存（Stack）」里，天然绝对隔离安全。

核心铁律：类自产打 `@Component`，第三方库用 `@Bean` 工厂包一层；注入必用构造器注入；单例 Bean 严禁留存有状态成员变量。
