# 泛型擦除与反射注解

泛型让编译器看懂类型，而反射与注解让框架在运行时拥有“透视”和“操控”对象的能力，是所有 Java 框架（Spring、MyBatis）的生命之源。

## 1. 泛型与类型擦除（Type Erasure）

Java 的泛型是**伪泛型**（为了兼容远古 Java 1.4）：
* **编译期**：做严格的类型边界检查，类型不对直接报错。
* **编译后（运行时）**：所有的泛型信息统统被抹平，全部退化成裸的 `Object`！
* **致命约束**：因为运行时根本没有 `T`，所以**绝对不能 `new T()`**，也不能写 `list instanceof List<String>`。

### 通配符 PECS 原则（Producer Extends, Consumer Super）
- **`? extends T`（只读上界）**：集合是生产者（Producer），你只从里面读数据出来（拿出来的肯定是 T），但**绝对不能往里写入数据**（因为编译器不知道具体是哪种子类）。
- **`? super T`（只写下界）**：集合是消费者（Consumer），你只往里面塞数据，安全无风险。

## 2. 注解（元数据贴纸）

注解本身没有任何逻辑，它是一张贴在类、方法、字段头上的**说明书**。必须给注解打上 `@Retention(RetentionPolicy.RUNTIME)`，它才能活到运行时被框架读取。

```java
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME) // 活到运行期，供反射读取
public @interface Column {
    String name();
}
```

## 3. 反射（代码的 X 光机）

反射可以在程序运行期间，突破语法限制，动态摸清一个对象的所有细节并强行执行：

```java
// 极简 ORM 核心原理：通过反射解析实体属性与注解
Class<?> clazz = user.getClass();
for (Field field : clazz.getDeclaredFields()) {
    if (field.isAnnotationPresent(Column.class)) {
        Column col = field.getAnnotation(Column.class);
        field.setAccessible(true); // 暴力突破：无视 private 权限强行读取值！
        Object value = field.get(user);
        System.out.println("列名: " + col.name() + " -> 值: " + value);
    }
}
```

核心铁律：泛型全在编译期，运行时皆为 `Object`；注解是静态说明书，配合反射的动态透视与调用，构成了现代 Java 框架的底层骨架。
