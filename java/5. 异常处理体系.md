# 异常处理体系

Java 的异常体系是代码安全运转的刹车系统。区别于前端的随手 `throw Error`，Java 区分了强迫捕获与自主上报两套轨道。

## 1. 受检异常（Checked）vs 运行时异常（Unchecked）

- **受检异常（Checked Exception，继承自 `Exception`）**：
  - 编译器按头强迫你处理（如 `IOException`, `SQLException`）。
  - **历史痛点**：如果不写 `try-catch`，就必须在方法签名上一层层向上写 `throws IOException`，代码污染极其严重。
- **运行时异常（Unchecked Exception，继承自 `RuntimeException`）**：
  - 编译器不强求在签名声明。代码发生逻辑错误（如 `NullPointerException`, `IllegalArgumentException`）或业务拒绝时触发。
  - **现代工程实践**：业务自定义异常一律继承 `RuntimeException`！

## 2. 自动释放资源：`try-with-resources`

任何实现了 `AutoCloseable` 接口的资源（文件流、数据库连接、网络 Socket），直接声明在 `try (...)` 的小括号里。代码跑完或抛异常时，**Java 会自动关门（调用 `.close()`），告别繁琐易错的 `finally` 嵌套**：

```java
// 小括号内创建的流会在退出时自动关闭
try (BufferedReader reader = new BufferedReader(new FileReader("data.txt"))) {
    String line = reader.readLine();
} catch (IOException e) {
    // 捕获到底层受检异常，包装为统一业务运行时异常往外抛，由外层接盘
    throw new BusinessException("读取配置失败", e);
}
```

核心铁律：非系统底层不写受检异常，业务异常一律继承 `RuntimeException`；释放流和连接必用 `try (...)` 小括号自动关门；严禁写空的 catch 吞掉异常。
