# 函数式与 Stream

Stream API 是 Java 的声明式数据加工厂。它将集合视为一条传送带，通过链式管道完成过滤、变形与聚合，告别嵌套循环。

## 1. Lambda 与单抽象方法契约（SAM）

Java 使用单箭头 `->` 表达函数（对标 TS 的 `=>`）。只要接口**只有一个抽象方法（SAM）**，就可以简写为 Lambda：

- `Predicate<T>`：`t -> boolean`（条件过滤，给 `filter` 用）
- `Function<T, R>`：`t -> r`（映射变形，给 `map` 用）
- `Consumer<T>`：`t -> void`（纯消费无返回，给 `forEach` 用）
- 方法引用 `::`：`User::getName` 是 `u -> u.getName()` 的极简写法。

## 2. 中间操作（惰性）vs 终端操作（点火）

Stream 是一次性的单程流水线：

- **中间操作（惰性挂号）**：`filter()`, `map()`, `sorted()`, `distinct()`。只登记加工规则，**绝不主动跑数据**！
- **终端操作（点火启动）**：`toList()`, `collect()`, `count()`, `reduce()`。一旦调用，整条传送带才真正通电启动；执行完后 Stream 即刻销毁关闭。

```java
// 过滤大单、打 9 折并求总额
int totalDiscount = orders.stream()
    .filter(o -> o.getAmount() >= 100)      // 中间：挂号过滤
    .map(o -> o.getAmount() * 9 / 10)       // 中间：挂号折算
    .reduce(0, Integer::sum);               // 终端：点火计算并聚合
```

## 3. 快递分拣分组（`groupingBy`）

将扁平的 List 自动归纳成以分类键为 Key、元素列表为 Value 的大字典：

```java
// 按订单状态分组，产出 Map<String, List<Order>>
Map<String, List<Order>> byStatus = orders.stream()
    .collect(Collectors.groupingBy(Order::getStatus));

// Java 16+ 极简只读转列表：
List<String> names = users.stream().map(User::getName).toList(); // 产物不可 add()
```

核心铁律：Stream 必须有终端操作才会真正执行；Java 16+ `.toList()` 生成只读集合，修改会抛异常。
