# Maven 工程化

Maven 是 Java 生态最主流的构建工具与依赖包管家。对标前端 npm/pnpm，负责依赖解析、编译测试与工程打包。

## 1. GAV 坐标（对标 package.json）

Maven 在 `pom.xml` 中使用 **GAV 坐标**（GroupId, ArtifactId, Version）精准定位依赖：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId> <!-- 组织反向域名 -->
    <artifactId>spring-boot-starter-web</artifactId> <!-- 项目模块名 -->
    <version>3.2.0</version> <!-- 版本号 -->
    <scope>compile</scope> <!-- 作用域 -->
</dependency>
```

- **依赖下载流向**：Maven Central 远程中央仓库 $\rightarrow$ 缓存在本地 `~/.m2/repository`。
- **作用域 Scope**：
  - `compile`（默认）：编译、测试、打进生产 jar 包全都要。
  - `test`：只在单测生效，打包时自动剔除（如 JUnit）。
  - `provided`：编译时要用，运行环境已自带，不打入包（如 Lombok、Servlet API）。

## 2. 标准生命周期（链式触发）

Maven 运行是串行流水线，**后置阶段会自动先跑所有前置阶段**：

```bash
# 常用命令链
mvn clean compile   # 删掉 target/ 重新编译字节码
mvn test            # 运行所有单测（单测只要挂了一个，流水线立刻中断！）
mvn package         # 串行跑 compile → test → package，打包出可运行的 .jar
mvn package -DskipTests # 紧急跳过单测打包
```

## 3. Maven Wrapper（`mvnw`）

团队开发必须使用项目根目录自带的 `mvnw`（对标前端 npx/corepack）。它会自动下载指定版本的 Maven 并运行，杜绝每台电脑 Maven 版本不一致导致的构建灾难。

```bash
./mvnw clean package  # 本机无需预装 maven，直接由 wrapper 驱动
```

核心铁律：后置构建必串行前置测试，单测挂了包就出不来；统一使用 `./mvnw` 抹平团队构建环境差异。
