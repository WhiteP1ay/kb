# Spring Boot Web 与异常

Spring Boot Web 是后端对接前端 HTTP 流量的总枢纽。掌握好参数反序列化、入参校验与全局异常接盘，是高可用 API 的核心地基。

## 1. 参数接收三剑客

| 请求方式 | Spring 注解 | 核心规则 |
| :--- | :--- | :--- |
| **URL 路径变量** (`/api/users/{id}`) | **`@PathVariable`** | 提取动态路由参数 |
| **URL Query 参数** (`?page=1&size=10`) | **`@RequestParam`** | 提取问号传参，支持默认值与必填校验 |
| **HTTP Body JSON 载荷** | **`@RequestBody`** | **必须显式添加**！否则 Spring 默认当 Query 解析，DTO 属性全为 null |

```java
@RestController // 等同于 @Controller + @ResponseBody，自动将对象序列化为 JSON
@RequestMapping("/api/articles")
public class ArticleController {

    @PostMapping
    public Result create(@Valid @RequestBody ArticleDto dto) {
        // @Valid 触发校验，@RequestBody 解析 JSON Body
        return Result.ok(articleService.save(dto));
    }
}
```

## 2. 参数声明式校验（Java 版 Zod）

在 DTO 字段上贴标签，在 Controller 参数前加 **`@Valid` 开关**：
- `@NotBlank(message = "标题不能为空")`：字符串非 null 且去除空格后长度 > 0。
- `@NotNull`：不能为 null。
- `@Min(value = 0, message = "不能为负数")`：数值下限。
- ⚠️ **暗坑**：如果 Controller 参数前**漏掉了 `@Valid`**，校验规则全部处于睡眠状态，脏数据直接进入业务层！

## 3. 全局异常处理与统一响应体

不要在每个 Controller 里重复写 `try-catch`！使用 **`@RestControllerAdvice` + `@ExceptionHandler`** 挂一个全局网兜：

```java
@RestControllerAdvice // 全局异常处理器（底层由 DispatcherServlet 总调度器集中接盘）
public class GlobalExceptionHandler {

    // 捕获业务自定义异常
    @ExceptionHandler(BusinessException.class)
    public Result handleBusinessException(BusinessException e) {
        return Result.fail(400, e.getMessage());
    }

    // 捕获参数校验失败异常（@Valid 拦截触发）
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result handleValidation(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getAllErrors().get(0).getDefaultMessage();
        return Result.fail(400, msg);
    }

    // 兜底系统异常
    @ExceptionHandler(Exception.class)
    public Result handleOther(Exception e) {
        return Result.fail(500, "系统开小差了，请稍后重试");
    }
}
```

核心铁律：POST 接收 JSON 必焊 `@RequestBody`；参数校验必开 `@Valid` 总开关；业务层大胆 throw 业务异常，外层 Advice 统筹包装成规范 JSON。
