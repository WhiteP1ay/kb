# SQL 落地核对清单

## 是什么

把一句中文需求翻译成 SQL 时，反复掉环的四个位置。语法全对、程序照跑、结果静默错，只有核对能拦住。

## 怎么用

交之前扫三遍，每遍只干一件事：

1. **名词映射**：需求里的每个名词，映射到具体的列或表达式。映射不上的，说明这个值要先算出来（「总金额」不是某一列，是 `sum(quantity * price)`；order_items 里的 `price` 只是单价）
2. **表达式计数**：同一个表达式在句子里出现了几次，数一遍再改，改完再数一遍（`sum(quantity * price)` 会同时出现在 select、having、order by）
3. **需求条件清点**：需求里有几个条件，SQL 里落地几个，逐条勾（漏过 8 月日期过滤、漏过 limit 3）
4. **结果形状**：跑之前先在脑子里画出结果长什么样，几行、哪些列。行数离谱就是条件漏了

## 关键点

- 掉环的类型是语义错，不是语法错，所以语法检查、`mypy` 式的静态检查一律抓不到
- 「看起来相关的列」不等于需求要的列，这是最常掉的一环
- 自纠能力强不代表不需要自查，问题恰恰出在交之前的自查环节

## 陷阱

- 只改一半：同一个表达式改两处漏第三处
- 自己加等号：需求说「超过」是 `>`，写成 `>=` 语义就变了
