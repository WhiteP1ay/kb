# 幂等键

## 是什么

幂等键（Idempotency Key）用于标识**一次用户操作**。客户端重复提交具有相同幂等键的请求时，服务端只执行一次业务操作，并为后续请求返回第一次的处理结果。

典型场景包括：

- 用户连续点击提交订单
- 请求已经成功，但响应在网络中丢失
- 客户端或网关自动重试请求

## 前端生成

幂等键可以由前端生成，通常使用随机 UUID：

```javascript
const idempotencyKey = crypto.randomUUID();

await fetch("/api/orders", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Idempotency-Key": idempotencyKey,
  },
  body: JSON.stringify(order),
});
```

关键在于幂等键的生命周期：一次用户操作只生成一次，网络重试必须复用相同的 Key。

```text
用户提交一次 → 生成 K1
第一次请求 → 使用 K1
请求超时后重试 → 继续使用 K1
用户确认再次下单 → 生成 K2
```

不能在每一次 HTTP 重试前都重新生成 UUID，否则服务端会把重试识别成新的操作。

## 服务端处理

服务端通常记录：

```text
用户 ID
幂等键
请求参数摘要
处理状态
业务数据 ID
响应结果
过期时间
```

数据库应设置唯一约束作为并发场景下的最终防线：

```sql
UNIQUE(user_id, idempotency_key)
```

处理规则：

```text
新 Key
→ 执行业务操作并保存结果

相同 Key + 相同参数
→ 不重复执行，返回之前的结果

相同 Key + 不同参数
→ 拒绝请求，可以返回 409 Conflict
```

幂等键应与当前用户、接口或业务类型绑定，不能代替登录鉴权。

## 服务端签发

幂等键也可以由服务端预先签发。例如先创建结算意图，再使用返回的 Key 提交订单。这种方式控制更强，但会增加一次交互。
