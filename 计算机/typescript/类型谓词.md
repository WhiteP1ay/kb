# 类型谓词

## 是什么

TypeScript 的类型收窄机制。`paramName is Type` 作为函数返回类型，告诉编译器：当该函数返回 `true` 时，参数已被收窄为指定类型。

```typescript
function isCoordinate(value: unknown): value is number {
  return typeof value === 'number' && Number.isFinite(value);
}
```

## 怎么用

没有类型谓词时，即使用 `if (fn(x))` 包裹，`x` 的类型也不会变：

```typescript
function isNum(v: unknown): boolean { return typeof v === 'number'; }

declare const x: unknown;
if (isNum(x)) {
  x.toFixed(2);  // ❌ x 仍是 unknown
}
```

加上 `v is number` 后：

```typescript
function isNum(v: unknown): v is number { return typeof v === 'number'; }

declare const x: unknown;
if (isNum(x)) {
  x.toFixed(2);  // ✅ x 被收窄为 number
}
```

## 关键点

- 对 `unknown` 类型的收窄收益最大——`unknown` 不加收窄几乎不能做任何操作。
- 可以替代手动 `as` 断言，更加类型安全。
- 编译器不会验证谓词逻辑是否正确——如果函数体写错了，TypeScript 不会报错，运行时会出问题。类型谓词本质上是开发者对编译器的承诺。

## 陷阱

类型谓词是"信任机制"而非"验证机制"。下面的代码 TypeScript 不会报错，但逻辑是错的：

```typescript
function isString(v: unknown): v is string {
  return typeof v === 'number';  // 逻辑错误，但 TypeScript 不管
}
```

务必确保函数体的运行时检查与实际类型匹配。
