# 生成器：yield 与惰性求值

## 是什么

函数体里出现 `yield`，函数就变身生成器函数。调用它**不执行函数体**，只返回一个生成器对象。每次 `next()`，函数体跑到 `yield` 暂停，把值交出去；下次 `next()` 从暂停的那一行续跑。Python 自动冻结整个函数现场（局部变量当前值），一行状态管理代码都不用写。

```python
def fib():
    a, b = 1, 1
    while True:
        yield a          # yield 在前：把当前值交出去
        a, b = b, a + b  # 然后才推进状态
```

## 关键点

- **工厂不开工**：`g = fib()` 零执行，函数体一行都没跑。开工是 `next(g)` 的事。
- **状态自动保存**：局部变量就是光标，Python 在 `yield` 处冻结、恢复。手写迭代器类要 `self.xxx` 维护状态，生成器全免。
- **单程票**：`next()`、`list()`、`for` 消费的是同一条流水线，共享同一个生成器状态。取走即无，不存档、不能重播、没有 `len`、不能下标。想再遍历，重新调用函数造新的。
- **结束自动**：函数体自然跑完就抛 `StopIteration`，不用手写；`for`/`list` 捕获它当正常结束。
- **无限流安全截断**：`while True` 不会卡死，因为每轮循环之间隔着一次 `next()` 调用，函数体不会自己一口气跑完。取有限个用 `for` + `enumerate` + `break`：

```python
for i, x in enumerate(fib()):
    if i == 10:
        break
    print(x)
```

## 生成器表达式：推导式的惰性弟弟

```python
[x * 2 for x in [1, 2, 3]]   # 急切：立刻算完整个列表进内存
(x * 2 for x in [1, 2, 3])   # 惰性：只造生成器，一个元素都没算
```

圆括号版就是生成器。`sum(x * 2 for x in huge_list)` 比 `sum([...])` 省一整份中间列表内存。生成器的规矩它全守：单程、没 `len`、不能下标。

## 陷阱（实测踩坑）

- **以为 `g = gen()` 执行了函数体开头**：不执行。`next()` 才启动，函数体从头跑到第一个 `yield`。
- **以为 `list(g)` 会从头重算**：不会。前两次 `next(g)` 取走 2 和 4 后，`list(g)` 只剩 `[6]`，不是 `[2, 4, 6]`。
- **状态推进放 `yield` 前**：先算后交，开头值不对，只能加计数器特判补洞，补洞又 off-by-one（斐波那契多 yield 一个 1）。正确顺序永远：`yield` 当前值在前，状态推进在后。
- 生成器函数名别加 `def generator()` 之类前缀，Python 不声明，函数体里有 `yield` 就是生成器函数。
