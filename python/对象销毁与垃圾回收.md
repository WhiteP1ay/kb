# 对象销毁与垃圾回收

## 是什么

`__del__` 是对象被回收前的钩子。CPython 用引用计数：引用数归零 → 立即回收 → `__del__` 同步触发。

## 怎么用

触发时机由引用计数决定，不由代码控制：

- `del 名字` 只是减一个引用，不一定触发 `__del__`
- 类属性/容器还持有引用时，del 变量名杀不死对象
- 循环引用要等 gc 循环回收器兜底，时机不确定

## 关键点

- 单例对象被类属性永生持有：`del a`、`del b` 后引用数还剩 1，直到类被回收才归零
- 解释器退出时清理也会兜底触发，但顺序不确定
- 想当场销毁单例：`Singleton.singleton = None` 连根拔

## 陷阱

- 绝不用 `__del__` 管资源（文件、连接）——时机不可控，用 with 上下文管理器
- `__del__` 里抛异常被静默吞掉
- 引用计数给人"我很确定"的错觉，循环引用一出现就露馅
