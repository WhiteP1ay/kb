# 事件循环与 async

## 协作式调度本质

Python 的 `asyncio` 是单线程下的**协作式事件循环调度器**：
- **心智模型（奶茶店单店员）**：只有一个店员服务多个顾客。顾客发起耗时操作后说“好了叫我（`await` 让出 CPU）”，店员立刻转头去服务下一个顾客。
- **协程创建不启动**：调用 `c = fetch()` 只返回一个处于冻结状态的 coroutine 对象，函数体**一行都不跑**。只有通过 `await`、`asyncio.run()`、`asyncio.gather()` 等调度时才正式开工。

```python
import asyncio

async def fetch_data(id: int):
    print(f"开始任务 {id}")
    await asyncio.sleep(1)  # 主动让出 CPU 控制权
    print(f"完成任务 {id}")
    return id * 10

async def main():
    # 并发执行多个协程
    results = await asyncio.gather(fetch_data(1), fetch_data(2))
    print("结果:", results)

asyncio.run(main())  # 显式启动事件循环入口
```

## 致命陷阱：同步阻塞直接卡死整个循环

`async` 针对的是 **I/O 密集型**任务，绝不能在协程中执行同步耗时阻塞。

- **`time.sleep` vs `asyncio.sleep`**：在 `async def` 里调用 `time.sleep(5)` 或同步网络请求（如裸 requests），相当于顾客抱住店员不放，整间奶茶店（整个事件循环里的所有任务）全部陪着卡死！
- **阻塞操作解法**：不可避免的同步阻塞代码，扔进独立线程池执行（FastAPI 中声明为普通 `def` 函数即可自动交给线程池）。

## Python 与 JavaScript 异步核心差异

| 特性 | JavaScript (Node / 浏览器) | Python (asyncio) |
| :--- | :--- | :--- |
| **事件循环** | 宿主环境默认常驻后台 | 必须由代码显式启动（`asyncio.run`） |
| **启动时机** | Promise 创建即开始在后台跑 | Coroutine 创建时彻底冻结，调度才跑 |
| **先创建后逐个 await** | 真正并发跑 | **无声退化为完全串行！** 必须用 `gather` 或 `create_task` |
