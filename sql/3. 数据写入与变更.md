# 数据写入与变更

## INSERT 显式列清单

向表中插入数据时，必须显式声明列清单，绝不要依赖隐式全列顺序。

```sql
-- 显式列清单：自增列、带默认值列直接省略；一个 VALUES 挂多个括号可批量插入
INSERT INTO orders (user_id, total) 
VALUES (11, 128.00), (12, 64.50);
```

- 省略列清单的 `INSERT INTO t VALUES (1, 2, 3)` 是位置参数地狱，表结构稍有增减列就会直接错位报错。

## ON CONFLICT（Upsert）

「存在即更新，不存在即插入」，避免先查后决定的往返开销。

```sql
-- 冲突时更新：excluded.price 指代本次传入的新数据
INSERT INTO products (name, price) VALUES ('tomato', 6.00)
ON CONFLICT (name) DO UPDATE SET price = excluded.price;

-- 冲突时静默跳过
INSERT INTO products (name, price) VALUES ('tomato', 6.00)
ON CONFLICT (name) DO NOTHING;
```

- 前提：`ON CONFLICT (列)` 里的列必须建有主键或唯一约束，否则直接报错。

## UPDATE 与 DELETE 安全

更新与删除必须显式指定 `WHERE` 条件，忘写会直接作用于全表每一行。

```sql
-- 原子扣减：行锁保证并发安全，绝不要先查后改
UPDATE products SET stock = stock - 2 WHERE id = 3 RETURNING stock;

-- 删除必须精确限定行
DELETE FROM orders WHERE id = 37;
```

- 最佳实践：WHERE 是保命符；执行后务必确认返回的影响行数（`UPDATE N` / `DELETE N`），改 1 行返回 8 行就是事故。

## RETURNING（写后即时返回值）

PostgreSQL 专有特性。写操作完成后直接返回受影响行的最新真实值，省去一趟二次查询。

```sql
-- 插入后即时拿回自增 ID
INSERT INTO orders (user_id, total) VALUES (15, 45.50) RETURNING id;

-- 扣库存后直接返回最新库存
UPDATE products SET stock = stock - 2 WHERE id = 3 RETURNING id, stock;
```

- 核心用途：拿回数据库生成的值（自增 ID、默认时间戳）或行锁扣减后的计算结果。
