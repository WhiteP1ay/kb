# 分组聚合与核对

## 聚合函数

吃一组行、吐一个计算值的函数（`count`、`sum`、`avg`、`min`、`max`）。

```sql
-- 表达式写在聚合函数内部：先逐行相乘算小计，再整体求和
SELECT sum(quantity * price) AS total_amount FROM order_items;
```

- `count(*)` 数所有行（包含 NULL），`count(列)` 只数该列非 NULL 的行。
- `sum` 遇到无匹配行时返回 `NULL` 而非 0，若需保底 0 用 `COALESCE(sum(x), 0)`。

## GROUP BY：分堆与压扁

本质是**把多行理成分堆文件夹，每堆压扁成最终的一行**（100 张发票按人名理成 3 堆，结果只出 3 行）。

```sql
-- 铁律：SELECT 只能选分组键或聚合函数，分组键记得带 id 避免同名被合并
SELECT u.id, u.name, count(*) AS order_cnt, sum(o.total) AS spent
FROM users u
JOIN orders o ON o.user_id = u.id
GROUP BY u.id, u.name;
```

- **报错根源**：小明的文件夹里有 5 张不同金额的发票，如果写 `SELECT name, total`，这一行该填哪张的金额？数据库猜不出来，所以直接报错拦截。
- **铁律**：SELECT 里只能出现**分组键本身**（文件夹封皮，组内一致），或者**聚合函数**（`sum/count/max`，把一堆算成一个确定数值）。
- 分组键必须能唯一区分实体：同名用户（id=1 和 id=3 都叫张三）若只按 name 分组会被并成一堆，分组键务必带上 `u.id`。

## HAVING 与 WHERE 的分工

两个过滤关卡，位置不同，分工不同：
- `WHERE`（理堆前扔掉）：在**分组前**筛行，先把不合要求的单张原始发票扔掉（不能使用聚合函数）。
- `HAVING`（理完堆后扔掉）：在**分组后**筛组，把整堆算完后总计不达标的文件夹扔掉。

```sql
SELECT user_id, sum(total) AS spent
FROM orders
WHERE created_at >= '2026-08-01'  -- 先筛行：能写在 WHERE 绝不写 HAVING
GROUP BY user_id
HAVING sum(total) > 200;          -- 后筛组：聚合结果只能用 HAVING 过滤
```

- 判别标准：条件里的值在分组前就已经确定的写 WHERE；等整堆算完才知道的写 HAVING。
