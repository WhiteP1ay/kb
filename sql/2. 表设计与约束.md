# 表设计与约束

## 引号与大小写

在 SQL 中，单引号管值，双引号管标识符（列名、表名）。

```sql
-- 单引号 = 字符串值
INSERT INTO users (email) VALUES ('a@b.com');
```

- 未加引号的标识符默认折叠为小写：`Users`、`USERS` 在数据库里都是 `users`。
- 加双引号的标识符区分大小写：`"Users"` ≠ `users`，自找麻烦别用。
- 最佳实践：**值永远单引号，表名列名小写不加引号**。

## 核心数据类型

### 金额与高精度：NUMERIC / DECIMAL
定点十进制数（PG 叫 `NUMERIC(p, s)`，MySQL 叫 `DECIMAL(p, s)`），以十进制存储与计算，无二进制浮点舍入误差。

```sql
price NUMERIC(10, 2)  -- 总长度 10 位，保留 2 位小数（整数最多 8 位）
```
- 铁律：涉及钱、交易额、汇率必须用 NUMERIC / DECIMAL，永远不要用 float 或 double。

### 时间戳：TIMESTAMPTZ
PG 中时间字段永远推荐用 `TIMESTAMPTZ`（带时区时间戳），底层统一存 UTC，外显时按客户端/会话时区自动换算。

```sql
CREATE TABLE orders (
    created_at TIMESTAMPTZ DEFAULT now()
);
```
- 铁律：禁止使用不带时区的裸 `timestamp`，避免服务器切时区引发全库时间错乱。

## 自增主键

自增主键在不同数据库中的推荐写法：

```sql
-- PG 现代推荐（SQL 标准）
CREATE TABLE products (id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY);

-- PG 旧式（语法糖，底层创建 sequence 序列）
CREATE TABLE products (id SERIAL PRIMARY KEY);

-- MySQL
CREATE TABLE products (id INT AUTO_INCREMENT PRIMARY KEY);
```

- 最佳实践：自增 ID 绝不要手填，手填会导致底层序列滞后，后续自动插入撞主键报 duplicate key。自增 ID 删行后不回退，别假设 ID 连续。

## 外键与删除联动（ON DELETE）

外键（FOREIGN KEY）表达父子表从属关系，外键写在子表上，`REFERENCES` 指向父表。

```sql
CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    -- 删订单时连带删除明细
    order_id INTEGER NOT NULL REFERENCES orders(id) ON DELETE CASCADE
);
```

三类删除联动策略：
1. `ON DELETE RESTRICT`（默认）：子表有引用则禁止删父表，用于订单、账单等核心数据防误删。
2. `ON DELETE CASCADE`：父死子随，父表删行连带删除子表行，用于订单明细等纯从属数据。
3. `ON DELETE SET NULL`：父表删行后子表外键置为 NULL（该列需允许 NULL），用于弱关联解绑。

## 五大完整性约束

约束是写死在数据库里的规则，应用层校验管体验，数据库约束保底线真相。

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,                        -- 主键（唯一 + 非空）
    email TEXT UNIQUE NOT NULL,                   -- 唯一约束与非空约束
    age INTEGER CHECK (age >= 0 AND age <= 150),  -- CHECK 范围校验
    department_id INT REFERENCES departments(id)   -- 外键约束
);
```

- 完整性违规错误码均为 `23xxx`（23505 唯一冲突、23503 外键失效、23514 CHECK 失败）。
