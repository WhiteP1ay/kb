# 联表查询 JOIN

跨表按引用展开，本质是**拿着快递单（订单）上的编号去名单（用户）里找人，拼成一张大宽表**。一条 SQL 由数据库内部完成拼接，避免在代码里循环查（防 N+1 问题）。

## INNER JOIN（对对碰：两边必须都对上）

两边按连接条件对等配对，任何一边落单的直接丢弃（没快递的人、没主人的单子全不出现）。

```sql
SELECT o.id, o.total, u.name
FROM orders o
JOIN users u ON u.id = o.user_id;  -- 拼的是键（id），不是名字
```

- **对称性**：谁在 FROM 谁在 JOIN 结果完全相同（像两人握手，谁先伸手结果一样）。
- **一对多展开**：张三有 2 笔订单，张三的名字就会出场 2 次（行数变多是正常的）。
- **落单即消失**：刚注册还没下过单的新用户，在 INNER JOIN 结果中彻底消失。

## LEFT JOIN（左边是亲儿子：谁在左边谁全勤）

左表全部保留，右表没配上的补 NULL。**这张报表里谁的数据绝对不能漏，谁就写在 LEFT JOIN 左边**。

```sql
SELECT u.name, o.id AS 订单号, o.total
FROM users u           -- users 在左边（亲儿子，全员到齐）
LEFT JOIN orders o ON o.user_id = u.id;
```

- 哪怕新用户一笔订单都没有，他也必须出场，右侧订单信息全填 `NULL` 陪跑。
- **换边就变天**：如果手抖写成 `FROM orders o LEFT JOIN users u`，订单成亲儿子，没下单的新用户再次蒸发。

## 反连接模式（排他查询：抓出没下单的人）

基于 LEFT JOIN 没配上的行右侧补 NULL 的特性，配合 `WHERE 右表主键 IS NULL` 即可实现反向排他筛选。

```sql
-- 查出从未下过单的用户（抓出订单号是 NULL 的人）
SELECT u.id, u.name
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
WHERE o.id IS NULL;
```

- 核心用途：排查“从未下过单的用户”、“从未被买过的商品”。
- 判空铁律：必须写 `WHERE o.id IS NULL`，写成 `= NULL` 永远匹配不到任何行。
