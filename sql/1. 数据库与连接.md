# 数据库与连接

## MySQL 架构与启停

MySQL 是典型的 C/S（客户端/服务端）架构。

- `mysql`：命令行客户端交互程序，只负责发指令和展示结果。
- `mysqld`：服务端守护进程（MySQL 数据库实例），负责真正的数据存取与请求响应。
- `mysqld_safe`：带故障监控与自动重启的服务端启动脚本。
- `mysql.server`：日常使用的启停管理脚本（间接调用 mysqld_safe）。

```bash
# 服务启停
mysql.server start
mysql.server stop

# 客户端免明文密码连接（本机可省略 -h）
mysql -h 127.0.0.1 -u root -p
```

## MySQL 请求处理链路

一条 SQL 在 MySQL 内部的流转链路：

1. **连接器**：TCP 握手，验证用户名、密码与权限。
2. **分析器**：词法与语法分析，确认 SQL 语法是否合法。
3. **优化器**：决定使用哪个索引、多表连接顺序，生成最优执行计划。
4. **执行器 + 存储引擎**：执行器调存储引擎（InnoDB 等）接口逐行存取数据。

核心认知：Server 层管语法解析与优化，存储引擎层负责底层磁盘数据存取。

## PostgreSQL 角色模型

PostgreSQL 权限体系底层统一为**角色（role）**，没有 root 用户概念。

- 角色带 `LOGIN` 属性才能登录连接（类似传统用户），不带则仅作为权限组。
- 安装后默认超级角色名为系统用户名（macOS）或 `postgres`（Docker）。

```sql
CREATE ROLE shop_user WITH LOGIN PASSWORD 'shop123';  -- 建带登录权限的角色
CREATE DATABASE shop_db OWNER shop_user;              -- 建库并移交所有权
```

最佳实践：业务服务永远使用专属 role + 独立 database，严禁用超级角色裸跑业务。

## Python 连接与事务（psycopg）

psycopg（Python 的 PostgreSQL 驱动）默认 `autocommit=False`。所有操作都在一个隐式事务中，必须显式 `conn.commit()` 数据才会落盘，否则关闭连接时全部自动回滚。

```python
import psycopg

conn = psycopg.connect("dbname=shop_db user=shop_user password=shop123")

# 必须显式 commit，否则关连接时全回滚
conn.execute("INSERT INTO products (name, price) VALUES (%s, %s)", ("onion", 3.50))
conn.commit()

conn.close()
```

避坑要点：
- 别套用 GUI 工具（DBeaver 默认自动提交）的直觉，写代码必须显式 `conn.commit()`。
- SQL 参数化防注入必须用 `%s`，严禁用 f-string 字符串拼接。
